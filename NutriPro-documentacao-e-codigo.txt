2. OBJETIVO E RECURSOS
----------------------

NutriPro é uma PWA React em português do Brasil para:

- autenticação e onboarding;
- metas de calorias, macros, fibra, hidratação e peso;
- diário por data e tipos de refeição pessoais;
- alimentos públicos/privados, favoritos e overrides;
- unidades, porções e densidades personalizadas;
- snapshots nutricionais históricos;
- água, peso, medidas corporais e avaliação física;
- tema claro/escuro/sistema e instalação PWA;
- uso offline do catálogo e fila de unidades/densidades.

Stack: React 19, TypeScript, Vite 8, React Router, TanStack Query, Firebase Auth,
Cloud Firestore, Dexie/IndexedDB, Vitest, Playwright, Axe e Firebase Emulator Suite.

3. INSTALAÇÃO
-------------

Recomendado:

- Node.js 22 ou 24 LTS;
- npm compatível com o Node;
- JDK 21 para Firestore Emulator;
- Chromium do Playwright.

Comandos:

    npm ci
    npx playwright install chromium
    npm run dev

Copie .env.example para .env e preencha a configuração Web pública do Firebase:

    VITE_FIREBASE_API_KEY=
    VITE_FIREBASE_AUTH_DOMAIN=
    VITE_FIREBASE_PROJECT_ID=
    VITE_FIREBASE_STORAGE_BUCKET=
    VITE_FIREBASE_MESSAGING_SENDER_ID=
    VITE_FIREBASE_APP_ID=
    VITE_USE_FIREBASE_EMULATORS=false
    VITE_E2E=false

Não colocar chaves privadas, contas de serviço, tokens ou senhas no frontend.

7. ONBOARDING — CONTRATO DE ESTADO
---------------------------------

Código conceitual implementado em src/lib/onboarding-state.ts:

    type OnboardingState =
      | { status: 'loading' }
      | { status: 'complete' }
      | { status: 'incomplete' }
      | { status: 'error'; error: unknown }

Uma falha de rede/permissão nunca é convertida em “incomplete”. A interface mostra:

    Não foi possível verificar seu perfil.
    Confira sua conexão e tente novamente.

O onboarding lê perfil, metas e peso inicial antes do batch. Reenvio e clique duplo não
duplicam o peso nem substituem createdAt.

9. UNIDADES, PORÇÕES E DENSIDADE
--------------------------------

Fluxos disponíveis:

- g/kg para massa e ml/l para volume;
- unidade e porção diretas;
- + nova medida;
- salvar para próximas vezes;
- usar só desta vez;
- tornar padrão;
- editar, duplicar, desativar, restaurar;
- excluir fisicamente somente quando não houver uso histórico.

Intervalos:

    amountPerUnit: 0,1 a 10.000 g ou ml
    gramsPerMl:    0,1 a 20

ID determinístico:

    ${userId}_${foodSource}_${foodId}_${normalizedUnitName}

Snapshot de um mealItem novo:

    unitProfileId
    unitLabelSnapshot
    amountPerUnitSnapshot
    baseMeasureSnapshot
    consumedBaseAmount
    nutrientBaseAmount

O histórico não é recalculado quando a medida muda.

12. AVALIAÇÃO FÍSICA
--------------------

Campos opcionais nulos são omitidos no create. No update, limpar um valor resulta em
deleteField(). Isso reduz armazenamento e custo de expressão das regras sem impedir
remoção. O E2E gravou avaliação manual, percentual, cintura e IMC calculado.

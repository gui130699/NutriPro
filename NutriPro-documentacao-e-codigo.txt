1. VISÃO GERAL
--------------

NutriPro é uma PWA responsiva para registro alimentar, hidratação, metas
nutricionais, evolução de peso e perfil de usuário. A interface está em
português do Brasil, possui autenticação por e-mail/senha e utiliza Firebase
Authentication, Cloud Firestore e Firebase Hosting.

Principais módulos da interface:
- Tela de acesso, cadastro e recuperação de senha.
- Onboarding inicial.
- Dashboard com progresso calórico, macronutrientes e hidratação.
- Diário alimentar por data com registro de alimento e água.
- Cadastro de alimentos e medidas de porção.
- Evolução de peso e gráfico de tendência.
- Perfil, metas, privacidade e logout.
- PWA instalável, cache e aviso de atualização.

3. ARQUITETURA
--------------

Frontend
  src/main.tsx
    -> QueryClient + BrowserRouter + registro do service worker.
  src/App.tsx
    -> Rotas públicas, privadas e verificação de configuração Firebase.
  src/hooks/useAuth.tsx
    -> Estado do usuário autenticado via onAuthStateChanged.
  src/services/nutrition-service.ts
    -> Operações de leitura e escrita do Firestore.
  src/lib/nutrition.ts
    -> Cálculos nutricionais puros e formatadores brasileiros.

Firebase
  Authentication
    -> Login, cadastro, logout e recuperação de senha.
  Firestore
    -> Collections profiles, goals, foods, mealItems, waterLogs,
       weightLogs, recipes e dailyNotes.
  Hosting
    -> Publicação do build Vite em nutripro-9115a.web.app.

GitHub Pages
  .github/workflows/deploy-pages.yml
    -> Gera dist/ a cada push para main e publica em /NutriPro/.


4. MODELO DE DADOS FIRESTORE
----------------------------

Coleções usadas pelo aplicativo:

profiles
  userId, dados de perfil, preferências e timestamps.

goals
  userId, calories, protein, carbs, fat, fiber, water_ml.

foods
  userId, nome, categoria, nutrientes por 100 g/ml, porções, visibilidade.

mealItems
  userId, date, mealName, snapshots nutricionais, quantidade e unidade.

waterLogs
  userId, date, amount_ml, logged_at e created_at.

weightLogs
  userId, logged_on, weight_kg, percentual de gordura e observações.

As regras de segurança exigem userId igual a request.auth.uid para operações
sobre dados particulares. Alimentos públicos somente são lidos por usuários
autenticados e devem ser administrados pelo Console Firebase ou por uma futura
função administrativa protegida.


5. INSTALAÇÃO LOCAL
-------------------

1. Instale Node.js 22 ou superior.
2. Clone o repositório.
3. Execute: npm install
4. Copie .env.example para .env.
5. Preencha VITE_FIREBASE_API_KEY e VITE_FIREBASE_APP_ID.
6. No Firebase Console, ative Authentication > E-mail/senha.
7. Execute: firebase login
8. Execute: firebase deploy --only firestore:rules,firestore:indexes
9. Execute: npm run dev

Comandos úteis:
- npm run dev       inicia o ambiente local
- npm run test      executa os testes unitários
- npm run build     gera o build de produção e o service worker
- npm run preview   abre o build local
- firebase deploy   publica Firestore e Hosting


6. DEPLOY
---------

Firebase Hosting
  1. npm run build
  2. firebase deploy --only hosting

GitHub Pages
  O workflow deploy-pages.yml é disparado automaticamente em pushes para main.
  As variáveis VITE_FIREBASE_API_KEY e VITE_FIREBASE_APP_ID devem existir em:
  Settings > Secrets and variables > Actions > Variables do repositório.

O Vite utiliza base /NutriPro/ no GitHub Actions e / nos demais ambientes.
Isso garante que scripts, CSS, manifest e rotas sejam encontrados nas duas
plataformas de hosting.


7. PWA E OFFLINE
----------------

- O manifest e o service worker são gerados pelo vite-plugin-pwa.
- A aplicação solicita atualização quando uma nova versão está disponível.
- src/lib/offline.ts fornece uma fila Dexie/IndexedDB com UUIDs de cliente.
- A implementação pode usar enqueueOffline e syncPending em mutações que
  precisarem sobreviver a indisponibilidade de rede.

Última validação desta versão:

- npm run build: aprovado.

- Firebase Hosting: deploy concluído.


9. DIRETRIZES DE SEGURANÇA
--------------------------

- Nunca versione o arquivo .env.
- Nunca exponha chave administrativa do Firebase no frontend.
- A API key web do Firebase é pública por natureza, mas deve ser restringida
  no Google Cloud Console para domínios e APIs necessários.
- Mantenha as regras firestore.rules publicadas antes de liberar o app.
- Revise as regras ao adicionar novas coleções ou papéis administrativos.
